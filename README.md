# 매일 성경 읽기 360일 — Firebase 설정 안내

가족이 같은 주소로 접속해 그날 읽을 범위를 보고, 기억나는 말씀을 적어 서로 나누는 앱입니다.
기록은 Firebase의 Cloud Firestore에 저장되어 모든 기기에 바로 반영됩니다.

> 지금은 **개발용**입니다. 로그인이 없어서 주소를 아는 사람은 누구나 기록을 읽고 고칠 수 있습니다.
> 가족 이름과 개인적인 내용은 로그인 기능을 넣은 뒤에 입력하세요.

---

## 1. 준비물

- Google 계정
- 앱 파일 `매일_성경읽기_360일_Firebase.html`
- (배포할 때) Node.js와 터미널

Firebase 설정값을 넣기 전에도 화면은 열립니다. 다만 상단에 "Firebase 설정 전이라 저장되지 않습니다."가 표시되고, 기록은 저장되지 않습니다.

---

## 2. Firebase 프로젝트와 웹 앱 만들기

1. https://console.firebase.google.com/ 에 접속해 새 프로젝트를 만듭니다.
   - Google 애널리틱스는 이 앱에 필요하지 않으므로 꺼도 됩니다.
2. 프로젝트 첫 화면에서 웹 아이콘(`</>`)을 눌러 웹 앱을 등록합니다.
   - 앱 닉네임은 아무 이름이나 괜찮습니다.
   - "Firebase 호스팅 설정" 항목은 체크하지 않아도 됩니다. 배포는 6장에서 따로 합니다.
3. 등록이 끝나면 `const firebaseConfig = { ... }` 코드가 표시됩니다. 이 부분을 복사해 둡니다.
   - 나중에 다시 보려면 **프로젝트 설정(톱니바퀴) → 일반 → 내 앱**으로 가면 됩니다.

---

## 3. 앱 파일에 설정값 넣기

앱 파일을 메모장 같은 편집기로 열고 `firebaseConfig`를 찾습니다. 그다음 중괄호 `{ }` 안의 값을 콘솔에서 복사한 값으로 **통째로** 바꿉니다.

```js
const firebaseConfig = {
  apiKey: '...',
  authDomain: '...',
  projectId: '...',
  storageBucket: '...',
  messagingSenderId: '...',
  appId: '...'
};
```

- 값을 손으로 고쳐 쓰지 말고 콘솔에 표시된 그대로 붙여 넣으세요.
  - 예를 들어 `storageBucket`은 프로젝트에 따라 `...appspot.com` 또는 `...firebasestorage.app` 형식입니다.
- 콘솔 코드에 `measurementId`가 함께 있으면 그대로 두어도 됩니다.
- `apiKey`는 웹 앱이라면 원래 공개되는 값입니다. 데이터 보호는 4장의 **보안 규칙**이 맡습니다.

---

## 4. Firestore 데이터베이스 만들기

1. 콘솔 왼쪽 메뉴에서 **Firestore**를 엽니다.
   - 메뉴 이름은 **Databases & Storage → Firestore** 또는 **Firestore Database**로 보일 수 있습니다.
2. **데이터베이스 만들기**를 누릅니다.
3. 위치를 고릅니다. 한국에서 쓴다면 `asia-northeast3 (서울)`이 가깝습니다.
   - 위치는 한 번 정하면 바꿀 수 없습니다.
4. 시작 모드는 **프로덕션 모드**를 고릅니다.
   - 테스트 모드는 프로젝트 전체를 누구에게나 열어 두고, 일정 기간 뒤에는 자동으로 막힙니다. 그래서 아래 규칙을 직접 넣는 편이 안전합니다.
5. 데이터베이스가 만들어지면 **규칙** 탭을 열고 내용을 아래 규칙으로 모두 바꾼 뒤 **게시**를 누릅니다.

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // 앱이 쓰는 문서 하나만 열어 둡니다. 나머지는 모두 막힙니다.
    match /families/default {
      allow read, write: if true;
    }
  }
}
```

이 규칙은 `families/default` 문서 하나만 열어 둡니다. 다만 그 문서는 **주소를 아는 누구나** 읽고 고치고 지울 수 있습니다. 실제로 쓰기 전에는 로그인 기능과 함께 규칙을 바꿔야 합니다(8장).

---

## 5. 내 컴퓨터에서 먼저 확인하기

파일을 더블클릭해 `file://`로 열면 브라우저에 따라 Firebase 연결이 안 될 수 있습니다. 간단한 웹 서버로 여는 것이 확실합니다.

```bash
# 앱 파일이 있는 폴더에서 실행
python -m http.server 8000
```

브라우저에서 `http://localhost:8000/매일_성경읽기_360일_Firebase.html`을 엽니다.

**확인할 것**
1. 상단의 "저장되지 않습니다" 문구가 사라지면 연결된 것입니다.
   - 오류 문구가 보이면 3장의 설정값과 4장의 규칙을 다시 확인하세요.
2. 말씀을 적고 **저장**을 누릅니다.
   - 처음에는 말씀 입력 칸 위에 이름 칸이 함께 나옵니다. 이름은 그 기기에만 기억됩니다.
3. 저장하면 그날이 **✓ 읽음**으로 바뀌고 **가족 기록**에 나타납니다.
4. Firebase 콘솔의 Firestore 데이터 탭에서 `families` → `default` 문서가 생겼는지 봅니다.
5. 다른 브라우저나 휴대폰으로 같은 주소를 열어 같은 기록이 보이는지 확인합니다.

---

## 6. 인터넷에 배포하기 (Firebase Hosting)

가족이 휴대폰으로 쓰려면 인터넷 주소가 있어야 합니다. Firebase Hosting은 HTTPS 주소를 무료로 제공합니다.

1. **파일 이름을 `index.html`로 바꿉니다.**
   - Hosting은 주소에 접속했을 때 `index.html`을 첫 화면으로 엽니다.
2. 빈 폴더(예: `bible-app`)를 만들고, 그 안에 `public` 폴더를 만든 뒤 `index.html`을 넣습니다.
3. 터미널에서 다음을 차례로 실행합니다.

```bash
npm install -g firebase-tools   # Firebase CLI 설치 (처음 한 번)
firebase login                  # Google 계정으로 로그인
cd bible-app
firebase init hosting
```

4. `firebase init hosting`의 질문에는 이렇게 답합니다.

| 질문 | 답 |
|---|---|
| 프로젝트 선택 | Use an existing project → 2장에서 만든 프로젝트 |
| public directory | `public` (그대로 Enter) |
| single-page app | `N` |
| GitHub 자동 배포 | `N` |
| `public/index.html` 덮어쓰기 | **`N`** (앱 파일이 지워지지 않게) |

5. 배포합니다.

```bash
firebase deploy --only hosting
```

6. 표시된 `https://프로젝트ID.web.app` 주소를 가족에게 보냅니다.
   - 아이폰은 Safari에서 **공유 → 홈 화면에 추가**를 누르면 앱처럼 쓸 수 있습니다.

앱을 고친 뒤에는 `public/index.html`을 새 파일로 바꾸고 5번 명령만 다시 실행하면 됩니다.

## 7. 사용 방법

- **읽기**: 첫 화면에 오늘의 일차와 범위가 나옵니다. **이전/다음** 버튼이나 일차 번호로 이동합니다.
- **기록**: 기억나는 말씀을 적고 저장하면 그날이 **✓ 읽음**으로 표시되고 입력 칸은 사라집니다.
- **가족 기록**: 지금 보고 있는 일차의 기록만 보입니다(예: "281일차 가족 기록"). 지난 기록은 **이전** 버튼이나 일차 번호로 그날로 가면 볼 수 있습니다.
- **이름**: 화면 왼쪽 아래 **이름 변경**을 누르면 바꿀 수 있습니다. 이미 쓴 기록의 이름도 함께 바꿀지 묻습니다.
- **수정**: 가족 기록에서 내 기록의 **수정**을 누르면 그 자리에서 고칠 수 있습니다. **저장** 또는 **취소**를 누릅니다.
- **관리자**(화면 맨 아래 버튼)
  - **순서**(구약부터/신약부터)와 **연도**를 고르고 **적용**을 누르면 그해 1일차부터 시작합니다.
  - 기록은 연도·순서·일차별로 따로 저장됩니다. 2027년으로 바꿔도 2026년 기록은 그대로 남고, 다시 2026년으로 돌아가면 볼 수 있습니다.
  - **엑셀로 내려받기**를 누르면 모든 연도의 기록을 엑셀에서 열 수 있는 파일(.csv)로 받습니다. 열은 연도, 순서, 일차, 읽을 범위, 이름, 기억나는 말씀, 작성일입니다.

---

## 8. 알아 두어야 할 한계

- **현재 일차는 가족 모두가 함께 씁니다.** 한 사람이 다음 날로 넘기면 다른 사람 화면도 함께 넘어갑니다.
- **모든 기록이 문서 하나에 들어갑니다.**
  - 두 사람이 거의 동시에 저장하면 나중 저장이 앞의 기록을 덮어써서 하나가 사라질 수 있습니다.
  - Firestore 문서 하나는 최대 1MiB이므로 기록이 아주 많아지면 저장이 안 됩니다.
- **로그인이 없습니다.** 주소를 아는 누구나 기록을 바꿀 수 있습니다. 작성자 이름도 직접 입력한 값이라 확인되지 않습니다.
- 로그인이 없는 동안은 누구나 기록을 지울 수 있으므로, 가끔 **엑셀로 내려받기**로 사본을 받아 두세요.

**정식으로 쓰기 전에 할 일**
1. Firebase Authentication으로 로그인을 추가합니다.
2. 기록을 한 건씩 별도 문서로 나눕니다(예: `families/{가족ID}/entries/{기록ID}`).
3. 현재 일차를 사람마다 따로 저장합니다.
4. 보안 규칙을 "로그인한 가족 구성원만 읽기, 본인 기록만 수정"으로 바꿉니다.
